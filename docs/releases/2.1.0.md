# MyCLI 2.1.0

Run long shell commands in the background while the model continues independent
work. Available only with `/tools medium` and `/tools full`.

- `BackgroundStart`, `BackgroundList`, `BackgroundOutput`, and `BackgroundStop`
  manage actual processes, current output, exit codes, cancellation, and timeouts.
- `/tasks` lists jobs; `/tasks output <id>` reads results; `/tasks stop <id|all>`
  stops work independently of the model.
- Session isolation, four-command concurrency, bounded output, temporary archives,
  and shutdown cleanup limit resource use and prevent stale status claims.
- Existing permission checks apply to command launches and stops.
- The vendored Cersei SDK is retained. Upstream's documented task tools only track
  records, so this release adds a MyCLI adapter using the existing tool interface.
- OpenAI cloud profiles accept optional `organization` and `project` fields.
  These send explicit routing headers for Responses and Chat Completions, fixing
  the GPT-6 access errors observed when the same API key worked in Codex with
  explicit organization/project routing.

Jobs live only within the current CLI process. No subagents, persistent supervisor,
or interactive terminals are included. See [background commands](../background-tasks.md)
for lifecycle behavior and limits.

Validation on Linux: 360 workspace tests passed (including 11 background/tier
checks). Local mock-provider CLI checks covered medium/full execution, simple-tier
exclusion, foreground work during background execution, output/stop tools,
single-shot and SIGTERM cleanup, interactive tier switching, `/tasks`, and EOF.
The Linux release binary was built and installed locally and reports `mycli 2.1.0`.
Live local-model demos also confirmed foreground coding and tests while background
commands run, incremental output retrieval, and successful completion reporting.
The routing fix passed 144 provider/CLI tests, live GPT-6 Luna and Sol responses,
and a Luna file-read tool round trip. Routing tests cover header transmission,
profile/client isolation, and invalid header rejection.
Remote release builds validate and package Linux and macOS binaries for ARM64 and
x86_64; their results are recorded in the linked GitHub Actions run.
