# MyCLI 2.3.5

Make local models that slip on tool-call details usable, notably flint (`mlx-community_flint-oQ8e`, `Flint-abliterated-Mix-24G`). Flint itself — confirmed from raw completions, not the server parser — writes tool names in lowercase (`bash` for `Bash`), uses `path` for `file_path` and `old_str`/`new_str` for Edit's `old_string`/`new_string`, and sometimes sends numbers as strings (`"timeout": "30000"`). Previously every such call failed with `Unknown tool` or `missing field`, and the model often misread the error and kept retrying.

The agent runner now normalizes each tool call once, right after the response arrives, so history, approval dialogs, rendering and execution all see the corrected call:

- A tool name is resolved case-insensitively when exactly one tool matches.
- `path`/`filePath`, `old_str` and `new_str` are renamed to the advertised argument only when the tool's schema defines the canonical name but not the alias. Glob and Grep keep their real `path` argument.
- String values are converted to a declared integer, number or boolean only when they parse exactly.

Input-validation errors also list the arguments the tool takes, the ones sent and the ones missing, so a model can correct the call on the next turn.

Validation: workspace tests pass, with new tests for each rule. Against oMLX, `mlx-community_flint-oQ8e` completed all 9 runs of a multi-step Read/Write/Edit/Bash task, and `Flint-abliterated-Mix-24G` completed all 11. Of 70 logged calls in one 24G batch, 36 needed and received a correction. The remaining failures are calls the model left incomplete or filled with invented arguments; the error hint let it recover every time.
